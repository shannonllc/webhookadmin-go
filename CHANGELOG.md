# Changelog

## 0.3.0 (2026-10-17)

- Comments and tests only: the request ID is described as the ID to quote when contacting support, and internal paths and local addresses were removed from comments and tests. No API changes.
- Retrying a delivery to a disabled endpoint (`Deliveries.Retry`), sending a test to one (`Endpoints.SendTest`) and starting a bulk resend for one (`Endpoints.Recover`) now return `ErrConflict` with `Code` `endpoint_disabled` instead of being accepted and then not sent. Fix the endpoint and set `Status` to `EndpointActive` first. Retrying a delivery whose endpoint was deleted returns `ErrNotFound`. `Delivery.EndpointStatus` (the endpoint's current status, or nil if deleted) tells you in advance.
- `MessageNoEndpoint` (`no_endpoint`): the consumer had no endpoint for the message when it was accepted. Such messages used to be listed as `MessagePending`. They are stored but not sent (not even if an endpoint is added later) and are not counted toward the monthly quota. `MessageListParams.Status` can be `MessageNoEndpoint`. If you switch on `Message.Status`, handle the new value.
- `Consumers.Delete(ctx, id)` for `DELETE /v1/consumers/:id`: deletes a consumer with its endpoints and the sources that deliver to it. Portal links for the consumer stop working and deliveries not yet sent are not sent.
- Sources: receive webhooks from other services (Stripe, GitHub, Shopify, Slack, Meta, Zoom, Standard Webhooks, a custom HMAC header, Basic authentication, an API key, or no verification) at a URL of their own, verify them and turn them into messages of a consumer. `Client.Sources` with `Create(ctx, SourceCreateParams)`, `List(ctx, *SourceListParams)` / `ListAll(*SourceListParams)`, `Get(ctx, id)`, `Update(ctx, id, SourceUpdateParams)`, `Delete(ctx, id)`, `SetSecret(ctx, id, secret)`, `RemoveSecret(ctx, id)`, `ListRequests(ctx, id, *SourceRequestListParams)` / `ListAllRequests(id, *SourceRequestListParams)` (with `Status` to list one status) and `ReprocessRequest(ctx, id, requestID)` (not retried on a 5xx) for `/v1/sources`. Types `Source` (with `Held`, the number of webhooks held while paused), `SourceConfig` (with `Query`, `VerifyToken`, `Username`, `ForwardHeaders` and `Response`), `SourceResponse`, `SourceRequest` (with `Method`, `ProcessedAt` and `Reprocessable`), `SourceRef`, and the `SourceProvider`, `SourceStatus` and `SourceRequestStatus` constants (including `SourceMeta`, `SourceZoom`, `SourceBasic`, `SourceAPIKey` and `SourceRequestHeld`). A paused source accepts and holds webhooks, and sends them on when set back to active.
- `Message.Source`: the source a message was received from (`ID`, the name at that time and `RequestID`), or nil.
- `DestinationSlack`, `DestinationTeams` and `DestinationChatwork` (Pro plan and above): post a chat message built from the message data (`text`, and optionally `title`, `lines` and `link`; otherwise the event type and the data as JSON) instead of the JSON body, without a signature. Slack and Teams take `DestinationParams{"credentials": map[string]string{"webhook_url": ...}}` (a Slack Incoming Webhook URL, or a Teams Workflows URL on `*.powerplatform.com` or `*.logic.azure.com`); Chatwork takes `{"room_id": ..., "credentials": {"api_token": ...}}`. `Attempt.Via` can be `slack`, `teams` or `chatwork`, and `Attempt.Ref` is the Chatwork `message_id` (nil for Slack and Teams).

## 0.2.1 (2026-09-29)

- Documentation only: the README and the type descriptions no longer name other webhook services. No API changes.

## 0.2.0 (2026-09-29)

- Polling endpoints: `EndpointCreateParams.Type` (`EndpointPolling`, with no `URL`), `Endpoints.ListPollerTokens(ctx, id)`, `Endpoints.CreatePollerToken(ctx, id, *PollerTokenCreateParams)` and `Endpoints.DeletePollerToken(ctx, id, tokenID)`. `NewPoller(endpointID, token, ...Option)` fetches the messages as the receiver with a poller token: `Poll(ctx, *PollParams)`, `Pages` (`*PollIter`) and `Messages` (`*Iter[PolledMessage]`). `EndpointPolling`, `Endpoint.LastPolledAt`, `PollerURL` on `EndpointWithSecret` and `EndpointDetail`, `Endpoint.URL` is empty for a polling endpoint, `DeliveryWaiting` and `Attempt.Via` `"poll"`.
- Destinations other than webhooks: `EndpointCreateParams.Type` and `.Destination` (`URL` is now omitted when empty), `EndpointUpdateParams.Destination`, `Endpoint.Type` and `.Destination`, `Attempt.Ref`, the `EndpointType` constants (`EndpointHTTP`, `DestinationSQS`, …), and `Endpoints.TestDestination(ctx, DestinationTestParams)` for `POST /v1/destinations/test`.
- Transformations: `Endpoints.GetTransformation(ctx, id)`, `Endpoints.SetTransformation(ctx, id, TransformationSetParams)`, `Endpoints.DeleteTransformation(ctx, id)` and `Endpoints.TestTransformation(ctx, id, *TransformationTestParams)` for `/v1/endpoints/:id/transformation`. `Endpoint.TransformationUpdatedAt`, `Attempt.Transform`, and the `cancelled` status on messages and deliveries (`MessageCancelled`, `DeliveryCancelled`, with constants for every `DeliveryStatus`).
- `Ordering` (`OrderingNone`, `OrderingFIFO`) on `Endpoint`, `EndpointCreateParams` and `EndpointUpdateParams`: `OrderingFIFO` sends deliveries to that endpoint one at a time, in the order the messages were accepted. `EndpointDetail.WaitingCount` is the number waiting behind the delivery being sent.
- `EndpointCreateParams.Secret`: import an existing signing secret (`whsec_…`, such as one from another webhook service) instead of generating one.
- `BodyFormat` (`BodyFormatStandard`, `BodyFormatRaw`) on `Endpoint`, `EndpointCreateParams` and `EndpointUpdateParams`: `BodyFormatRaw` sends the message data itself as the body (signed as sent) instead of `{"type", "timestamp", "data"}`.
- `SendMessageParams.TransformationsParams`, passed to transformations as `webhook.transformationsParams`.
- Transformations: `Transformation.Enabled` and `Transformation.Variables` (read as `webhook.env`). `TransformationSetParams` now sends only the fields that are set (`Code`, `Enabled *bool`, `Variables Nullable[map[string]string]`), so `Code` is optional once saved. `TransformationTestParams.Variables` and `.TransformationsParams`. The code limit is now 51,200 characters. `Transformation` is no longer comparable with `==` (it has a map).
- `EndpointUpdateParams.FixedIP`.
- `MessageListParams.Since`: only messages created at or after a time (Unix milliseconds).
- `PollParams.EventTypes` and `PollParams.After`: read only some event types, or start from a time when there is no iterator. `Pages` and `Messages` keep them on every page.

## 0.1.0

- First release: messages, consumers, endpoints (including bulk resend, retry policy and compatibility signature), deliveries, event types, consumer portal links, and webhook signature verification. Same API coverage as the Node.js SDK 0.3.0.
